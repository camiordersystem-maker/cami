# 本部・店舗の専用運用アカウント

## 権限と認証

専用の本部担当は `editor`、店舗担当は承認済み `member` を使います。最高管理者の認証情報は配布しません。既存の閲覧専用ユーザーを昇格させず、別のアカウントとして扱います。

Worker Secret `CAMI_MANAGED_AUTH` は検証・本番を分離し、許可したローカルID・認証サービスID・メール・権限・既存ハッシュのフィンガープリントを紐付けます。パスワード照合は既存NeonのManaged Better Authで実行し、不調時にbcryptへ自動フォールバックしません。一般登録・認証メール・有料プランは有効化しません。

本部は注文、出荷、請求・入金、商品、在庫、店舗情報の更新権限を持ちます。最高管理者専用の管理者作成・監査ログ・機能設定は許可しません。店舗は自店の発注、配送先、注文履歴、約款同意を扱います。他店や本部の管理APIへはアクセスできません。

## 利用開始前

- 本部で店舗名、担当者、電話、住所、掛け率を実際の情報に更新します。未登録の値を実在の取引先情報と扱わないでください。
- 店舗で実際の配送先を登録し、約款を確認します。発注は本番の注文となり、受注LINEにも通知されます。
- 実在庫は推測して登録しません。現物確認後に本部が登録します。在庫0の間は注文できません。
- 仮のメール識別子はメール受信できません。正式担当者が決まったら、個人ごとの業務用アカウントへ切り替え、仮アカウントを停止します。

## 制約と停止方法

- 専用アカウントのパスワード変更は運用担当者が対応します。会員画面にはその案内を表示し、従来のWorker内bcrypt更新は409で明示的に拒否します。現在の画面からの自己変更は提供していません。
- 本部の無効化、店舗の承認取消・停止、ローカルハッシュ変更で、ログイン済みセッションも拒否します。
- 停止はローカルアカウントの無効化／停止を優先し、Secret削除だけを停止手段にしません。
- 一般の管理者・店舗ユーザーは従来認証のままです。今回の対応だけで、一般登録・新規会員発行・パスワードハッシュ作成を含む全認証フローの無料枠適合を保証しません。
- 本番の業務更新テストは行いません。権限の通過は空入力の検証エラーと読取りで確認し、実際の更新は利用者の業務判断で行います。

## 記録

アカウント追加は既存ユーザーを変更せず、承認済みの専用2件と作成監査ログだけを追加します。認証用スキーマには対応するユーザーと認証情報を追加します。パスワード・ハッシュ・接続文字列は公開ログやGitへ保存しません。ロールバック時はWorkerの直前バージョンへ戻し、発行した2件を停止します。注文や在庫を巻き戻しません。

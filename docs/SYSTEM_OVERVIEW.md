# Cami受発注システム システム概要

Baseline: RC2 `dcde0d0ce4dea0a4b17f4204a4556ee14a2c849c`

## 1. 目的

Cami本部と加盟店・取引先の間で、BtoBの商品注文、注文確認、在庫、請求、会員情報、契約・連絡を一元管理するWebシステムです。

主な利用者は次の2系統です。

- **店舗・加盟店（member）**: 商品を注文し、注文状況・請求書・お知らせ・契約書等を確認する。
- **本部（admin）**: 会員審査、注文処理、在庫、月次請求書、商品、約款、お知らせ等を管理する。

## 3. 注文の基本状態

`src/lib/order-status.ts`をsource of truthとします。

```text
pending
  ├─> confirmed ─> shipped ─> delivered
  ├─> cancelled
  └─> cancel_requested ─> cancelled

confirmed
  ├─> shipped
  ├─> cancelled
  └─> cancel_requested
```

管理画面のキャンセル却下処理では、キャンセル申込前の状態へ戻すための情報を保持します。

## 4. 金額計算

注文時に、会員ランクの掛け率を用いて商品単価を計算します。

概念上:

```text
箱単価 = 商品定価 × 1箱の本数 × 会員ランク掛け率
商品小計 = 箱単価 × 箱数
注文小計 = 各商品小計の合計
消費税 = 注文小計 × TAX_RATE
合計 = 注文小計 + 消費税
```

現在の税率定数は`src/lib/constants.ts`の`TAX_RATE`を参照してください。送料カラムは存在しますが、店舗注文画面では「別途ご連絡します」として扱われます。

## 5. 在庫の基本原則

- 注文作成時に在庫を引き当てる。
- 在庫不足の場合は注文を成立させない。
- キャンセル承認時に引当在庫を返却する。
- 在庫変更は在庫移動履歴へ記録する設計。
- 手動調整と注文・キャンセルによる自動増減を二重に行わない。

詳細は`DATA_MODEL.md`と`BUSINESS_FLOWS.md`を参照してください。

## 6. 請求の基本原則

月次請求書は会員・年月を指定し、その月に属する`confirmed / shipped / delivered`注文を集計して発行します。同一会員・同一年月の重複発行を拒否します。

発行時の対象注文は`invoice_orders`に固定し、後から注文ステータスが変わっても発行済み請求書の内訳が変わらないようにします。旧請求書でスナップショットが存在しない場合には後方互換の期間集計処理があります。

## 7. 追加機能

`feature_flags`で次の追加機能を個別にON/OFFできます。

- 支払期限超過アラート
- クイック再注文
- 請求書PDF相当の印刷ページ・メール送付
- CSV一括発注
- 低在庫バッジ表示
- お知らせメール通知
- 会員向け注文CSVダウンロード

正確なキーと説明は`src/lib/constants.ts`を参照してください。

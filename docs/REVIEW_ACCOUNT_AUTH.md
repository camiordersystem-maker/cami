# 確認用アカウントの認証

## 適用範囲

クライアントの画面確認用に、期限付きの閲覧専用アカウント1件だけを Managed Better Auth に接続する。一般の管理者・会員の認証方式は変更しない。この機能の合格は、一般利用者を含む本格運用の合格を意味しない。

## 設定と停止

- Worker の Secret `CAMI_REVIEW_AUTH` に環境ごとのポリシーを保存する。値・パスワード・接続文字列はリポジトリやログへ記録しない。
- ポリシーは環境、認証サービスURL、ローカル管理者ID、認証ユーザーID、メール、既存ハッシュのフィンガープリント、有効期限を厳密に指定する。
- 認証用ユーザーは管理者が事前発行する。一般登録、認証メール送信、外部OAuthは無効化する。
- ローカル管理者は `viewer` かつ有効である必要がある。既存ハッシュの変更、期限切れ、無効化でアクセスを拒否する。セッション利用時にも検証する。
- 期限を延長する場合は、確認担当者・目的を再確認してからポリシーだけを更新する。期限を無条件で延長しない。
- 緊急停止は対象アカウントの無効化を優先する。ポリシー削除だけを停止手段としない。削除すると既存の通常認証へ戻るため、アカウント自体の停止を確認する。

## 障害・ロールバック

認証サービス障害時は認証を拒否し、旧方式へ自動フォールバックしない。画面には再試行・担当者への連絡を案内し、上流エラーや認証情報を表示しない。既存業務データを書き換えず、Worker の直前バージョンへ戻せるようバージョンを記録する。コードを戻す場合も、確認用アカウントを停止し、期限・閲覧制限を迂回させない。

## 確認項目

検証環境で正否ログイン、ユーザー一致、期限・無効化・ハッシュ変更の拒否、既存セッション失効、閲覧API、更新APIの403、同時読取10件、スマートフォン・文字拡大・操作ガイドを確認してから本番へ追加する。注文・在庫等の業務更新はこの試験で行わない。
